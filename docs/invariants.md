# Invariants 
An invariant is a property that must remain true across requests, concurrency, retries, crashes,
and deployments. Later stages must map each production invariant to an enforcement mechanism and
an executable test.

## Target product invariants

| ID | Invariant | Intended future enforcement |
|---|---|---|
| INV-001 | A tenant cannot read, stream, cancel, retry, or download another tenant's object. | Tenant-scoped authorization and storage keys |
| INV-002 | One idempotency key and one request meaning identify one logical submission. | Transaction plus unique constraint and request hash |
| INV-003 | Reusing an idempotency key with different request meaning is rejected. | Stored request hash checked atomically |
| INV-004 | An accepted job is never silently lost. | Durable transaction before acknowledgement |
| INV-005 | At-least-once execution cannot create multiple visible final artifacts. | Idempotent step and deterministic artifact identity |
| INV-006 | Every final artifact identifies its input checksum, pipeline version, processor version, and attempt provenance. | Relational constraints plus immutable object metadata |
| INV-007 | Progress can repeat, but the client converges to authoritative state. | Durable events, sequence numbers, and state reconciliation |
| INV-008 | A terminal job cannot return to a non-terminal state. | Domain transition rules and database constraints |

## Invariants enforced in Stage 1

- Job identifiers are UUIDs generated by the application.
- Legal job transitions are enforced by the domain model.
- Terminal job states cannot transition again.
- A successful job always contains one deterministic result.
- The result checksum is computed from the exact UTF-8 input bytes.

## Known violations and limitations

- INV-001 is not applicable yet because there are no users or tenants.
- INV-002 and INV-003 are not implemented; repeated POST requests create different jobs.
- INV-004 is violated by process restart because the repository is memory-only.
- INV-005 is not yet tested under retries because there are no workers.
- INV-006 contains only processor version and input checksum in Stage 1.
- INV-007 is not implemented because processing is synchronous.

These are recorded debts with planned learning stages, not hidden production claims.
